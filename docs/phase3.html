Unsupervised Learning Analysis: E-Commerce Order Segmentation¶

Project Overview¶

Building on the cleaned e-commerce dataset established in our data preprocessing phase, this report applies unsupervised learning techniques to uncover latent structure within order behavior. Specifically, we pursue two complementary objectives:

  1. Customer Order Segmentation via K-Means Clustering — grouping orders by their numerical characteristics (basket value, quantity, freight proportion, and product diversity) to identify distinct purchasing profiles that can inform targeted marketing and logistics strategies.
  2. Market Basket Analysis via Association Rule Mining — discovering statistically significant co-occurrence patterns between product categories, payment methods, and order sizes to surface actionable cross-sell and promotional opportunities.

Together, these analyses translate raw transactional data into strategic business intelligence.

Environment Setup¶

The following libraries underpin the full analytical pipeline. pandas and numpy handle data manipulation; matplotlib and seaborn drive visualization; sklearn provides preprocessing and clustering utilities; and mlxtend supports the Apriori-based association rule mining workflow.

Part 1: Unsupervised Learning¶

Objective¶

With a clean order-level dataset in hand, we apply unsupervised learning to surface hidden structure in purchasing behavior. The goal is to group orders by shared numerical characteristics — order value, item quantity, freight proportion, and product variety — into distinct customer segments. These segments form the basis for targeted promotions, differentiated logistics planning, and personalized recommendation strategies.

1. Data Preprocessing for Unsupervised Learning¶

1.1 Constructing the Order-Level Feature Matrix (all_orders_df)¶

Before clustering can be applied, the dataset must be structured so that each row represents exactly one order. From the cleaned dataset, we extract and derive the following features:

  • basket_size — total monetary value of the order
  • basket_qty — total number of items
  • freight_ratio — the share of the order value attributable to shipping (total_freight_value / order_total_value), a proxy for logistics intensity
  • product_diversity — the breadth of distinct product types relative to basket size (num_unique_products / num_items), capturing whether customers shop narrowly or broadly
  • top_product_category, payment_type, order_size_category — categorical dimensions used later in association mining

Division-by-zero cases (zero-value or empty orders) are handled explicitly. Remaining missing values in categorical columns are replaced with "Unknown", and numerical columns are zero-filled.

2. Determining the Optimal Number of Clusters¶

2.1 K-Means Inertia Sweep (k = 3 to 9)¶

Before committing to a cluster count, we systematically evaluate K-Means across a range of values (k = 3 to 9) on the analysis sample. Only the four numerical features — basket_size, basket_qty, freight_ratio, and product_diversity — are used, as clustering on raw numerical scales would bias results toward high-magnitude features. All features are therefore standardized using StandardScaler prior to fitting.

For each k, we record the inertia — the sum of squared distances between each order and its assigned cluster centroid. Inertia decreases monotonically as k increases; the objective is to identify the point at which additional clusters yield diminishing returns in compactness.

In [6]:
# 2.1: K-Means inertia sweep across k = 3 to 9 on standardized numerical features

num_cols = ["basket_size", "basket_qty", "freight_ratio", "product_diversity"]
X = orders_analysis_df[num_cols].copy()

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

k_values = list(range(3, 10))
inertia_values = []

for k in k_values:
    km = KMeans(n_clusters=k, random_state=37, n_init=10)
    km.fit(X_scaled)
    inertia_values.append(km.inertia_)

2.2 Elbow Method — Selecting the Optimal k¶

The Elbow Method plots inertia against k to visually identify the inflection point at which the marginal gain in cluster compactness begins to plateau. This inflection — the "elbow" — represents the most parsimonious cluster count: enough structure to be meaningful, without overfitting spurious micro-segments.

Based on the plot below, we select k = 4 as the optimal configuration, as this marks a clear change in the rate of inertia reduction before the curve smooths out further.

4. Market Basket Analysis (Association Rule Mining)¶

4.1 Methodology Overview¶

Market Basket Analysis is an unsupervised technique that quantifies co-occurrence patterns across discrete transaction attributes. Rather than predicting an outcome, it surfaces rules of the form "when X is present, Y is also present with high probability" — invaluable for understanding multi-dimensional customer behavior.

In the e-commerce context, this helps answer questions such as:

  • Which payment methods are preferred for which product categories?
  • Do certain order sizes correlate with specific product types?
  • What multi-attribute patterns exist across category, payment channel, and basket size?

Association rules are evaluated along three key metrics:

Metric Definition
Support How frequently a pattern appears across all transactions (0–1)
Confidence Probability of the consequent given the antecedent (0–1)
Lift How much more likely the rule is versus random chance (> 1 = positive association)

We apply the Apriori algorithm to the categorical features of all_orders_df to discover frequent itemsets and generate high-lift rules.

4.2 Transaction Encoding¶

To apply the Apriori algorithm, each order must be represented as a "basket" of discrete items. We construct a transaction list where each order contributes exactly three tagged items—one per categorical dimension:

  • cat_{top_product_category} — the dominant product category
  • pay_{payment_type} — the payment method used
  • size_{order_size_category} — the order size class (Small / Medium / Large)

The prefixes ensure items from different dimensions remain distinguishable after encoding.

4.3 Apriori Algorithm — Frequent Itemsets and Rule Generation¶

Using the mlxtend library, the workflow proceeds in three steps:

  1. One-hot encoding via TransactionEncoder — converts the transaction list into a Boolean DataFrame where each column represents a unique item.
  2. Frequent itemset mining via apriori() with min_support = 0.01 — retains only item combinations appearing in at least 1% of all orders, balancing pattern coverage against noise.
  3. Rule generation via association_rules() with metric = 'lift' and min_threshold = 1.0 — produces all rules where co-occurrence is at least as likely as independent random chance.

4.5 Rule Interpretation and Sensitivity Analysis¶

  1. The top three rules suggest that large orders are strongly linked to furniture/decor, while medium-sized baskets (often with credit card payment) are more associated with bed/bath/table purchases, indicating distinct shopping missions by basket size.

  2. The strongest association is the size_Large ↔ cat_furniture_decor combination (highest lift), meaning these items co-occur far more often than expected by chance.

  3. This likely happens because furniture items are typically bought in bulk home purchases, and paid by credit card possibly by installments or credit card rebates. On the other hand, size_Med + bed/bath/table items are common household replenishment purchases where customers buy in moderate quantities and paid using credit card for convenience.

  4. When min_support is reduced to 0.005, more niche and low-frequency rules appear (often higher lift but less generalizable), lowering support captures the "Long Tail" — we see rules for rare items (like musical instruments or art). While these have high Lift, they are less useful for broad business strategy because they represent such a tiny portion of total sales. Meanwhile increasing it to 0.3 keeps only very common patterns and removes many specific and useful associations. In conclusion, it might be ideal to lower min_support to extract more meaningful and insightful patterns from datasets compared to common patterns, depending on the business needs.

4.6 Business Recommendations¶

  • Prioritize large furniture baskets with payment support: For customers in cat_furniture_decor with size_Large, offer installment/BNPL and targeted checkout promotions to reduce abandonment on high-ticket (expensive) orders to hit credit card rebates.

  • Run medium-basket card promotions: Since medium baskets are strongly linked with card payment patterns, launch category-specific credit-card cashback bundles (especially home/bed-bath-related items).

  • Deploy rule-based cross-sell recommendations: Use high-lift pairs in cart and checkout ("frequently bought together" by category + size) to increase average order value and conversion.

Project Summary¶

Our Analytical Journey¶

This report documents the end-to-end data science workflow applied to an e-commerce orders dataset across three analytical phases:

Data Preprocessing (Phase 1) — Four raw relational tables (orders, order_items, order_shipping, payments) were consolidated into a single order-level analytical record. The pipeline addressed missing values via statistical imputation (median for numerical, mode for categorical), enforced logical business constraints (valid monetary and quantity fields), and engineered derived features including order_value_per_item and order_size_category. The result was a clean, deduplicated dataset persisted as ecommerce_orders_cleaned.csv.

Supervised Learning (Phase 2) — Classification models (Logistic Regression, Decision Tree, and Random Forest) were trained to predict the payment method (payment_type) from order attributes. After encoding and scaling, Random Forest delivered the strongest performance across all evaluation metrics, with its ensemble structure providing robustness against class imbalance and capturing the non-linear patterns that characterize real-world transaction data.

Unsupervised Learning (Phase 3) — Documented in full in this notebook. K-Means clustering (k = 4) segmented orders into four behaviorally distinct groups defined primarily by basket value and freight intensity. Market Basket Analysis then surfaced high-lift associations between product categories, payment types, and order sizes — most notably the strong link between large orders, furniture/decor categories, and credit card payment. Together, these findings translate raw transactional data into actionable customer segments and cross-sell intelligence.
